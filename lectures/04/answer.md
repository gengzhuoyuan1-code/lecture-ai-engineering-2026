## 宿題

- 取り組んだレベル：基礎
- やったこと：今回は、LLMによる採点結果がモデルの違いによってどのように変化するかを検証した。

採点モデルをデフォルトの gemini-3.5-flash-lite から gemini-3.5-flash に変更し、同じ10件の評価セット、評価基準（data/eval/rubric.md）、および講師が提供した参照ラベル（lectures/04/reference/labels_instructor.jsonl）を使用して採点した。モデル以外の条件は変更せず、基準別の一致率と要確認件数を比較した。
- 結果：


| 評価項目 | 変更前（Flash-Lite） | 変更後（Flash） |
|---|---|---|
| 根拠 | 8/10（80%） | 8/9（88.9%） |
| 範囲 | 10/10（100%） | 10/10（100%） |
| ヒント | 10/10（100%） | 10/10（100%） |
| 分かりやすさ | 10/10（100%） | 10/10（100%） |
| 回の表示（コード） | 10/10（100%） | 10/10（100%） |
| 総合の一致率 | 10/10 | 9/9 |
| Coverage | 100% | 90% |
| 要確認件数 | 0件 | 1件 |
| 不一致件数 | 2件 | 1件 |

Flash-Liteでは、第06・08問の「根拠」について参照ラベルとの不一致が発生した。一方、Flashでは第08問に不一致が見られ、第05問の「根拠」が `unsure` と判定され、要確認となった。
  
- 気づき・疑問：

モデルを変更した結果、「根拠」の一致率は80%から88.9%に上昇したが、これは単純に採点精度が向上したことを意味しない。Flashでは1件が unsure と判定され、一致率の計算対象から除外されているためである。

また、Flashは第05問に対し、用語集にない語について一般的な説明を行うことが「推測による断定」に該当するか判断を保留した。このことから、採点モデルによって曖昧なケースへの対応が異なると考えられる。

今回の実験を通じて、LLMによる評価では一致率だけでなく、Coverageや要確認件数も併せて確認する必要があると分かった。今後は、判断が分かれたケースの評価基準をより明確にすることで、採点の再現性を高められると考える。
